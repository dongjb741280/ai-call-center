# 02 · 业务流程

> 流程图基于 `voxai-call` 模块实际代码梳理（`FsListen`、`Fs*Handler`、`cc.command.*`、`cc.acd.*`、
> `cc.websocket.handler.*`、`CallCdrService`）。图使用 Mermaid。

## 0. 总体架构与事件驱动模型

`FsListen` 连接 FreeSwitch（`cc_station` 中 `application_type=4` 的媒体服务），订阅全部 ESL 事件，
按事件名通过 `HandlerContext` 分发到 `@HandlerType` 标注的处理器。呼叫链路状态保存在 Redis（`CacheService`），
核心对象为 `CallInfo`（一次通话）与 `DeviceInfo`（通话中的一个「腿」/设备）。

```mermaid

    end
    subgraph voxai-call
        WS["WebSocket<br/>Ws*Handler"]

        ACD["GroupHandler<br/>ACD 队列"]
        CMD["cc.command.*<br/>VDN/转接/溢出"]
        CDR["CallCdrService<br/>话单/录音"]

    WS --> CDR
    CDR --> DB

```

## 1. 呼入流程（Inbound）

客户拨打企业特服号，FreeSwitch 应答后触发 `CHANNEL_ANSWER`，`FsAnswerHandler.matchVdnCode` 用被叫号码
匹配 `cc_vdn_phone` 得到 VDN，进入 `VdnHandler` 按有效日程路由。

```mermaid
flowchart TD
    A[客户拨入特服号] --> B[FreeSwitch 应答<br/>CHANNEL_ANSWER]
    B --> C["FsAnswerHandler<br/>matchVdnCode 匹配 vdn_phone"]
    C --> D{"匹配到 VDN?"}
    D -- 否 --> H1[挂机]
    D -- 是 --> E["VdnHandler<br/>查有效日程 vdn_schedule"]
    E --> F{"路由类型<br/>routeType"}
    F -- "1 技能组" --> G1["进技能组 GroupHandler<br/>见 ACD 流程"]
    F -- "2 放音" --> G2["播放音频 playback"]
    G2 --> G2a{"放音类型 playType"}
    G2a -- "按键导航" --> G2b["收键 vdn_dtmf"]
    G2a -- "转技能组/IVR/路由/挂机" --> G2c["放音后 doNextCommand 转目标"]
    F -- "3 IVR" --> G3["transferIvrHandler<br/>调用 voxai-ivr 服务"]
    F -- "4 坐席" --> G4["transferAgentHandler<br/>呼指定坐席"]
    F -- "5 外呼" --> G5["transferCallHandler<br/>转外线"]
    G1 --> TALK[通话]
    G4 --> TALK
    G5 --> TALK
    TALK --> H["挂机 CHANNEL_HANGUP_COMPLETE"]
    H --> CDR["落话单 call_log/call_detail/call_device<br/>上传录音 MinIO<br/>话单推送 notify_url"]
```

## 2. 呼出流程（坐席外呼）

坐席通过 WebSocket 或 REST 发起外呼，`CallCdrService.makeCall` 创建 `CallInfo`，经媒体网关
`bgapi originate` 呼坐席，坐席应答后呼客户，客户应答后桥接。

```mermaid
flowchart TD
    A["坐席发起外呼<br/>WS_MAKE_CALL / REST makeCall"] --> B["CallCdrService.makeCall<br/>创建 CallInfo + device"]
    B --> C["选路由网关 route_getway<br/>（按被叫匹配）"]
    C --> D["originate 呼坐席分机/SIP/手机"]
    D --> E["坐席应答 CHANNEL_ANSWER<br/>NEXT_CALL_OTHER"]
    E --> F["呼客户号码"]
    F --> G["客户应答 CHANNEL_ANSWER<br/>NEXT_CALL_BRIDGE"]
    G --> H["uuid_bridge 桥接坐席与客户"]
    H --> I[通话]
    I --> J[挂机 → 落单]
```

## 3. ACD 排队与分配流程

电话进入技能组后的核心流程，含指定坐席、记忆坐席、溢出策略、排队与定时分配。

```mermaid
flowchart TD
    A[进入技能组 GroupHandler] --> B[记录 CallDetail 技能组节点]
    B --> C{"指定坐席?<br/>DESIGNATE_AGENT"}
    C -- 是且空闲 --> C1[呼叫指定坐席]
    C -- 否 --> D{"记忆坐席?<br/>group_memory"}
    D -- 命中且空闲 --> D1[呼叫记忆坐席]
    D -- 否 --> E["取有效溢出策略<br/>getEffectiveOverflow"]
    E --> F{"处置类型<br/>handleType"}
    F -- "1 排队" --> G["加入队列 PriorityQueue<br/>按排队策略计算优先级"]
    G --> G1["播放排队音 queue.wav"]
    F -- "2 溢出" --> H["OverFlowHandler<br/>转 组/IVR/VDN"]
    F -- "3 挂机" --> H2[挂机]
    G1 --> LOOP["acd() 每秒扫描"]
    LOOP --> K{"队列超时?"}
    K -- 是 --> L["queueTimeout<br/>超时溢出 or 挂机"]
    K -- 否 --> M{"有空闲坐席?"}
    M -- 否 --> LOOP
    M -- 是 --> N["取空闲坐席<br/>按分配策略 AgentStrategy 优先级"]
    N --> O["呼叫坐席 transferAgentHandler"]
    O --> P["坐席应答 → 桥接 → 通话"]

    subgraph 队列与坐席池
      Q1["callInfoMap<br/>技能组→呼叫队列"]
      Q2["agentInfoMap<br/>技能组→空闲坐席"]
    end
```

### 3.1 分配策略（`cc.acd.assign` / `AgentStrategy`）

| 策略实现 | 含义（对应 `strategy_value`） |
| --- | --- |
| `LongReadyAssign` | 1 最长空闲时间 |
| `TotalReadyAssign` / `TotalReadyTimesAssign` | 2 最长平均空闲 |
| `LeastAnswerAssign` | 3 最少应答次数 |
| `LeastTalkAssign` | 4 最少通话时长 |
| `TotalAfterTimeAssign` | 5 最长话后时长 |
| `PollAssign` | 6 轮选 |
| `RandomAssign` | 7 随机 |
| `AgentCustomAssign` | 自定义（`customExpression` SpEL / `cc_group_strategy_exp`） |

### 3.2 排队策略（`cc.acd.lineup` / `LineupStrategy`）

| 策略实现 | 含义（对应 `busy_type`） |
| --- | --- |
| `DefaultLineupStrategy` | 1 先进先出 |
| `VipLineupStrategy` | 2 VIP 优先 |
| `CustomLineupStrategy` | 3 自定义表达式 |

## 5. 坐席状态机

`AgentState` 枚举定义了坐席完整状态，`GroupHandler.agentFree/agentNotReady` 维护空闲坐席池。

```mermaid
stateDiagram-v2
    [*] --> LOGIN: 签入
    LOGIN --> READY: 置闲
    READY --> NOT_READY: 置忙
    NOT_READY --> READY: 置闲
    READY --> TALKING: 呼入分配/呼出接通
    TALKING --> AFTER: 通话结束(话后)
    AFTER --> READY: 话后结束/自动空闲
    AFTER --> NOT_READY: 置忙
    TALKING --> CONSULT_TALKING: 发起咨询
    TALKING --> CONFERENCE_TALKING: 三方会议
    CONSULT_TALKING --> TALKING: 咨询结束
    note right of AFTER
      话后自动空闲间隔：
      agent.after_interval / group.after_interval
    end note
```

## 6. 挂机与落单流程

```mermaid
flowchart TD
    A[任一方挂机<br/>CHANNEL_HANGUP_COMPLETE] --> B["记录该设备挂机原因/结束时间<br/>计算录音时长"]
    B --> C["落 call_device 明细"]
    C --> D{"是主叫侧挂断<br/>cdrType<=3 且未结束?"}
    D -- 是 --> E["挂断其余所有设备"]
    E --> F["最后一个设备挂机 → hangup()"]
    D -- 否 --> F
    F --> G["落 call_detail 流程轨迹"]
    G --> H["落/更新 call_log 主话单"]
    H --> I["清空坐席通话状态 → NOT_READY"]
    I --> J["清空 CallInfo 缓存"]
    J --> K{"配置 notify_url?"}
    K -- 是 --> L["推送话单 + call_device 明细<br/>（失败记录 push_log）"]
    K -- 否 --> M[结束]
```

## 8. 坐席状态订阅（TCP，供第三方系统）

`TcpServer` 提供坐席状态订阅，`Sub*Handler` 处理订阅事件，用于第三方系统（CRM 等）实时获取坐席状态与通话事件。

| 订阅事件 | 说明 |
| --- | --- |
| `SubLogin` | 登录订阅 |
| `SubMakeCall` / `SubAnswer` | 呼叫/应答事件 |
| `SubStartCall` / `SubStopCall` | 通话开始/结束 |
| `SubPlayFile` / `SubQueuePlay` / `SubQueuePlayStop` | 放音事件 |
| `SubTransferTo` | 转接事件 |
