# 08 · 技能与技能组配置

## 业务关系

技能是企业内独立维护的能力字典，例如“退款处理”“英文服务”，可被多个技能组使用。三条关系分别维护：

- **坐席与技能组**：`cc_agent_group` 记录组成员和主技能组（`is_primary`）。加入技能组不会自动获得技能。
- **坐席与技能**：`cc_skill_agent` 记录坐席具备的技能及等级 `rankValue`。
- **技能组与技能**：`cc_skill_group` 记录组使用的技能及等级条件、匹配顺序和占用率配置。绑定技能不会自动把具备该技能的坐席加入组。

VDN 可以将来话送入技能组；坐席成员关系决定组内成员范围。技能组绑定与坐席技能等级是两类独立配置，不能相互替代。

## 页面操作

1. 在“技能”页面新增技能，填写名称（2–16 字符）和可选备注（填写时 1–100 字符）。技能没有单一的所属技能组，也没有普通/VIP 类型字段。
2. 选择技能，在右侧添加坐席并设置 1–100 的整数等级；已有坐席可以修改等级或移除该技能。移除技能不改变坐席的技能组成员关系。
3. 在“技能组”的编辑窗口中维护坐席列表，成员关系通过“保存坐席关系”单独保存；移出主技能组时，有其他保留组则需选择替代主技能组。
4. 在技能组编辑窗口的“技能列表”中选择技能字典里的技能，配置等级条件、技能等级、匹配顺序和占用率，点击“保存技能路由”。该操作单独保存组技能配置，不依赖窗口底部基本信息保存。

技能页面显示绑定的技能组数量及组名。没有组绑定时显示“未用于路由”；绑定信息加载失败时显示状态未知，不能据此认定没有绑定。这里的标记反映技能组绑定情况，不证明技能组已被 VDN 引用，也不证明呼叫引擎已使用全部匹配规则。

技能被技能组使用时，页面提示先在技能组中移除；后端也会拒绝删除仍绑定技能组或坐席的技能。

## 技能组技能保存接口

`PUT /voxai-admin/config/group/{id}/skills` 中的 `{id}` 是技能组主键。请求示例：

```json
{
  "skillList": [
    {
      "skillId": 30,
      "levelValue": 1,
      "rankType": 3,
      "rankValueStart": 1,
      "rankValue": 70,
      "matchType": 2,
      "shareValue": 100
    }
  ]
}
```

- `skillList` 必传，最多 10 项；空数组清空当前组的技能绑定，遗漏的旧绑定会被删除。应提交希望保留的完整列表。
- `skillId` 是技能字典主键，不能使用组技能关联记录的 `id`；技能必须属于当前企业且有效，不允许重复。
- `levelValue` 为必填组技能等级字段，区别于坐席能力等级 `rankValue`。
- `rankType`：0 不限等级、1 小于等于、2 等于、3 大于等于、4 大于。该枚举以当前 `SkillGroupVo` 为准；旧 SQL 注释中的枚举与当前接口不同，不能直接套用。
- `rankValue`、`rankValueStart` 均为 1–100；即使条件为不限等级，请求也要满足字段校验。当前编辑器新增项为这两个字段设置默认值 1。
- `matchType`：1 由低到高，2 由高到低；`shareValue` 为 1–100 的占用率配置。
- 组必须属于当前企业；新增、更新、删除绑定在同一事务中完成，写入失败回滚。

## 坐席技能接口

以下路径中的 `{skillId}` 都是技能字典主键，坐席参数为坐席记录主键，不是工号或技能关联记录主键。

- `GET /voxai-admin/config/skill`：分页查询独立技能字典。
- `GET /voxai-admin/config/skill/{skillId}`：技能详情及 `skillAgents`。
- `POST /voxai-admin/config/skill/agent/{skillId}`：添加坐席，例如 `{"agentIds": [7, 8], "rankValue": 80}`。
- `PUT /voxai-admin/config/skill/agent/{skillId}`：修改等级，例如 `{"agentId": 7, "rankValue": 90}`。
- `DELETE /voxai-admin/config/skill/agent/{skillId}`：移除坐席技能，例如 `{"agentIds": [7]}`。

坐席管理也可统一编辑其技能，见 [坐席管理](07-坐席管理.md)。

## 当前呼叫引擎能力边界

组技能保存接口完成配置落库。当前代码尚未体现 ACD 按 `cc_skill_group` 的全部等级条件、匹配顺序和占用率执行筛选的完整链路，因此不能把保存成功当作这些规则已经参与实际呼叫分配的证明。

已有的 `AgentCustomAssign` 会把坐席的技能等级注册为自定义分配表达式变量，例如技能 30 对应 `#skill_30`；因此，即使没有技能组绑定，坐席技能仍可能被自定义表达式使用。技能页面“未用于路由”具体表示没有组技能绑定，不代表所有自定义策略都不会读取该技能。坐席技能变更后需重新登录以更新呼叫服务中的坐席配置；重新登录也不会补足尚未实现的组级条件筛选能力。
