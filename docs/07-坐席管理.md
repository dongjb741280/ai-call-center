# 07 · 坐席管理

## 操作方式

坐席列表的“编辑”和详情中的“编辑坐席”打开同一编辑表单，包含基本信息、技能组、坐席技能三个部分。编辑前通过详情接口加载完整配置。

- **基本信息**：维护名称、分机、手机接听号码、坐席类型、话后时长、外显号码、振铃时长、录音和状态。外显号码通过可搜索下拉选择当前企业已启用的被叫号码（`cc_company_phone.type=3`、`status=2`）；清空表示不指定坐席号码，呼叫时回退到主技能组的被叫显号池。已有坐席的工号不可修改；账户、时间戳及在线状态为只读信息。编辑时密码留空保留原密码，新建时必须填写密码。
- **技能组**：可加入多个组，并从已选组中指定一个主技能组；没有加入任何组时主技能组为空。列表中的蓝色“技能组”按钮提供单独调整入口，技能组详情中的坐席列表显示主技能组标记。
- **坐席技能**：可添加、删除技能并调整等级，最多 20 项，不允许重复，等级为 1–100 的整数。加入技能组与拥有技能是独立配置，不会互相自动继承。

新建坐席也支持同时配置技能组和技能；批量创建后需要通过编辑或“技能组”入口补充配置。详情加载失败时禁用保存，保存接口返回业务错误时保留编辑窗口。技能组和技能配置保存后，坐席需要重新登录，使呼叫服务使用新配置。

## 管理接口

以下路径包含前端代理前缀 `/voxai-admin`；路径参数 `{id}` 为坐席记录主键，不是工号 `agentId`。

- `GET /voxai-admin/config/agent`：坐席列表，主技能组筛选基于关联表的 `is_primary=1`。
- `GET /voxai-admin/config/agent/{id}`：完整详情，含技能组与坐席技能。
- `GET /voxai-admin/config/phone`：号码列表；坐席编辑器按 `type=3` 查询，并只将启用号码作为新选择项。
- `POST /voxai-admin/config/agent`：新增坐席。
- `PUT /voxai-admin/config/agent/{id}`：统一更新基本信息、技能组和技能。
- `PUT /voxai-admin/config/agent/{id}/groups`：仅更新技能组。
- `GET /voxai-admin/config/skill`：分页查询技能字典，供技能选择使用。

统一更新请求示例（新增时还须提供 `passwd`）：

```json
{
  "agentId": "1001",
  "agentName": "客服一",
  "agentCode": "8001",
  "sipPhone": "13800000000",
  "loginType": 1,
  "agentType": 1,
  "afterInterval": 5,
  "display": "12345",
  "ringTime": 30,
  "record": 1,
  "status": 1,
  "groups": {"groupIds": [10, 20], "groupId": 20},
  "skillAgents": [{"skillId": 30, "rankValue": 50}]
}
```

- `agentType`：1 普通坐席，2 班长；`ringTime` 为 1–600 秒，`afterInterval` 不小于 0。
- `sipPhone`：页面显示为“手机接听号码”，保存到 `cc_agent.sip_phone`。选择手机接听模式（`loginType=3`）时，系统使用此号码呼叫坐席；SIP / WebRTC 模式使用关联的 SIP 号码。该字段用于坐席接听，与外显号码 `display` 分别配置。
- `display`：坐席指定的被叫显号号码文本；为空时 WebSocket 外呼使用主技能组被叫显号池中的号码。WebSocket 外呼请求显式传入的号码仍优先于坐席配置。编辑时若原号码已停用或不在号码列表中，表单会保留并回显该值，用户可改选有效号码或清空。
- 密码由前端转换为 SHA256 十六进制字符串（64 位）再提交，后端使用 BCrypt 存储。编辑时不提交 `passwd` 表示保留密码。
- `groups` 不传或为 `null` 时保留关系；`{"groupIds": [], "groupId": null}` 清空关系。有成员组时 `groupId` 必须属于 `groupIds`，且只能指定一个主技能组。
- `skillAgents` 不传或为 `null` 时保留技能；空数组清空技能。技能和技能组必须属于当前租户且有效。
- 基本信息、技能组及技能在同一事务中保存，任一校验或写入失败都会回滚。

单独保存技能组的请求体直接使用 `{"groupIds": [10, 20], "groupId": 20}`，不再包裹 `groups`。

## 数据关系与升级

主技能组以 `cc_agent_group.is_primary` 为准，`cc_agent.group_id` 已移除。详情返回的 `groupIds` 表示全部成员组，`groupId` 是根据关联表计算的主技能组，不能当作坐席主表字段写入。旧库升级请核对并按脚本说明执行 [主技能组迁移脚本](sql/migration_20261103_agent_primary_group.sql)。

坐席技能保存到 `cc_skill_agent`，编辑字段为 `skillId` 和 `rankValue`。`rankType`、`matchType`、`shareValue` 属于 `cc_skill_group` 的组级技能规则，不属于坐席技能编辑字段。关系图及表结构见 [数据模型](03-数据模型.md)。

技能字典和技能组规则的完整操作与接口见 [技能与技能组配置](08-技能与技能组配置.md)。技能页面的绑定标记表示配置关系，实际呼叫分配能力以该文档的能力边界说明为准。
