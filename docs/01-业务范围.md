# 01 · 业务范围

## 1. 系统定位

本系统是一个**多租户、面向海量人工呼入/呼出场景**的企业级 AI 呼叫中心平台，也可作为 AI 智能无人呼叫的底座。
它解决的问题是：把「一通电话」从呼入/呼出，经过号码识别、路由、排队、分配、转接、录音、落单，最终到统计与监控，
全链路地自动化管理起来。

三条主线：

1. **呼入**：客户拨打特服号 → VDN 识别 → 技能组排队 → ACD 分配坐席 → 通话 → 落单。
2. **呼出**：坐席主动外呼 / 外呼任务自动外呼 → 呼叫客户 → 通话 → 落单。
3. **运营**：企业/坐席/技能/号码/路由配置、话单/录音、监控、统计报表、权限与计费。

## 2. 多租户模型

几乎每张业务表都带 `company_id`（企业 ID）。`cc_company` 是租户根节点，支持父子结构（`pid`/`id_path`），
并通过以下字段控制租户能力与计费：

- 计费：`bill_type`（呼出/呼入/双向/免费）、`pay_type`（预付费/后付费）、`balance`（余额）。
- 额度：`agent_limit`（坐席数）、`group_limit`（技能组数）、`ivr_limit`（IVR 通道）、`outbound_limit`（外呼并发）、`group_agent_limit`（单组坐席上限）。
- 隐私与安全：`hidden_customer`（隐藏客户号码）、`secret_type`（坐席密码复杂度）、`secret_key`（验证密钥）、`cdr_encrypt_push`。
- 录音：`record_storage`（保留月数）、`record_file_type`、`record_encrypt`。
- 话单推送：`notify_url`（通话结束回调地址）。

#### 3.6.1 字冠、网关组与媒体网关的业务关系

平台主动建立一段呼叫时，按「目标号码 → 字冠 → 网关组 → 媒体网关 → FreeSWITCH 拨号」选择出口。
这里的目标号码既可以是客户号码，也可以是坐席分机、坐席手机或转接号码。

- **字冠**：号码开头的一段数字，用于区分目的号码并选择网关组。例如 `021` 可配置为上海固话线路，`100` 可配置为内部 `1001` 等分机线路，`*` 可作为默认规则。这些是号码规划示例，不是系统内置的号码分类。
- **网关组**：组织可供某类号码使用的网关；一个字冠绑定一个网关组，一个组可关联多个网关。网关组现在支持轮询（默认）、按权重和顺序主备；顺序主备只在明确的线路故障时进入下一网关。
- **媒体网关**：在本项目中是 FreeSWITCH 的拨号出口配置，对端可以是运营商 SIP 中继、实体语音网关或其他电话系统。行业中的实体媒体网关还可能负责 SIP/IP 语音与 E1、模拟电话线路之间的转换。

配置顺序为：**先创建媒体网关，再创建网关组并关联网关，最后创建字冠并绑定网关组**。
`company_id=0` 的字冠作为全局规则，与当前企业的字冠一起加载。

#### 3.6.2 号码、显号与网关字段

以坐席 `1001` 呼叫客户 `13800138000`、希望客户看到企业号码 `02112345678` 为例：
`1001` 是坐席端号码，`13800138000` 是客户端的被叫号码，`02112345678` 是发往客户端时设置的主叫显号。
显号最终是否按配置显示，取决于线路商的授权和处理规则。

字冠负责**选路**；网关的 `callerPrefix` / `calledPrefix` 负责给实际送出的主叫/被叫**添加前缀**。
例如线路要求被叫前加 `9`，则 `calledPrefix=9` 会把客户目标号码改成 `913800138000`，不能把该前缀与字冠规则混为一谈。

`mediaHost` / `mediaPort` 用来构造对端 SIP 拨号地址，并非 RTP 语音端口；`profile` 在实际命令中是 Sofia SIP profile，
不是拨号计划 XML 文件名。配置了主机地址时，拨号形式为 `sofia/<profile>/<号码>@<主机>:<端口>`；
主机地址为空时则使用 `user/<号码>` 呼叫注册用户。`sipHeader1..3` 用于携带对接要求的额外 SIP 信息。

`cc_sip_gateway` 管理网关注册账号及在线地址、注册周期等信息；`cc_route_getway` 管理拨号出口，二者职责不同。
FreeSWITCH 站点决定由哪台媒体服务器执行呼叫，媒体网关决定该服务器将电话发往哪里。
SIP 负责拨号、振铃、接听和挂机等信令，RTP 主要传输语音；信令接通与语音正常需要分别验证。

#### 3.6.3 呼入与主动拨号的边界

**呼入入口不经过字冠选路**：运营商已将电话送到 FreeSWITCH，平台按被叫的企业接入号码匹配 `cc_vdn_phone`，
找到所属企业与 VDN，再进入 IVR、技能组排队、ACD 分配等业务。

但呼入分配到坐席后，平台仍需主动呼叫坐席端。当前 `TransferAgentHandler` 会按坐席号码调用字冠选路；
呼入后转外线也会由 `TransferCallHandler` 按转接号码选路。因此应按**是否需要主动建立新的呼叫腿**判断是否使用字冠，
不能理解为「整通电话是呼入，就完全不需要网关配置」。具体流程见 [业务流程 §2](02-业务流程.md#2-呼出流程坐席外呼)。

坐席向外拨打 `10010`、`10086` 等短特服号码，同样需要字冠、网关组和媒体网关；这与后台的呼入特服号/VDN 配置用途不同。
线路是否支持短号码、是否需要前缀以及接续到哪个地区，由线路商约定。若内部 `100` 字冠覆盖了分机号码，
应为 `10010` 等外部号码配置更具体的规则，并检查默认 `*` 规则及实际送出的号码，避免送入内部分机出口。

#### 3.6.4 号码改写和网关选择

字冠的主叫/被叫改写规则采用统一语义：`callerChange` / `calledChange` 表示删除号码开头的位数，
`callerChangeNum` / `calledChangeNum` 表示删除后拼接的新前缀；例如 `calledChange=1`、`calledChangeNum=9`，
会把 `13800138000` 变成 `93800138000`。`0` 加空前缀表示不改写。改写发生在网关前缀之前，
随后才应用媒体网关的 `callerPrefix` / `calledPrefix`。

网关组策略由 `selectionStrategy` 控制：`ROUND_ROBIN` 轮询、`WEIGHTED` 按关联表 `weight` 分配、
`FAILOVER` 按页面中的网关顺序使用主备。网关被识别为线路故障后进入 30 秒冷却，冷却期间不会被新呼叫选中。
只有未接通且未进入振铃、并且挂机原因为明确线路故障时才会为当前通话尝试下一网关；忙线、拒接、无人接听、已振铃或已接通不会自动换线。

#### 3.6.5 当前实现边界

以下结论基于当前运行时代码，配置字段存在不等于已执行：

- `GatewayRouter` 按字冠长度倒序读取，`CacheService.getRouteGetway` 命中首条即停止；实际条件是严格 `startsWith`，`route="*"` 作为最后的默认规则。
- `*` 是任意号码匹配项，并且明确排在所有号码字冠之后。
- 命中字冠但网关组没有可用网关时返回 `null`，不会继续尝试下一条字冠；这是避免绕过租户明确路由策略。
- 外呼任务保留“同一次任务尝试不自动重拨”的边界；故障冷却只影响后续呼叫的网关选择。
- 网关组的权重和顺序保存在 `cc_route_getway_group`；部署前需要执行 `docs/sql/migration_20261110_gateway_routing.sql`。

代码依据：`CacheService.initCompany/getRouteGetway`、`RouteCallMapper.selectListByMap`、`FsListen.originate`、
`FsParkHandler.inboundCall`、`TransferAgentHandler.hanlder`、`TransferCallHandler.hanlder`。

## 4. 业务范围边界

**已实现**：多租户、坐席/技能组/技能、VDN/IVR/AI 路由、IVR 引擎（`voxai-ivr`）、ACD 排队与溢出、记忆坐席、
转接/咨询/会议/监控、话单/录音（MinIO）/推送、统计报表、权限、TCP 状态订阅、号码路由网关。
